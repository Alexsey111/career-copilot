# Career Copilot — Production Blueprint v2

## Executive Intent

Цель v2 — превратить текущий MVP из локально-демонстрационного приложения в масштабируемый AI-powered career platform с безопасным пользовательским контуром, платёжной моделью и мультиканальным доступом.

v2 — это не “ещё фичи”.
Это переход от **application prototype** к **operational product system**.

# 3. Technical Domains

---

## 3.1 Identity & Access

### Required

* email/password auth;
* social/OAuth optional;
* Telegram identity linking;
* session tokens (JWT + refresh);
* ownership checks.

---

### Security model

Passwords:

* `argon2id` preferred;
* fallback `bcrypt`.

Sessions:

* short-lived access token;
* rotating refresh tokens.

---

---

## 3.2 Data Security

### Principles

Do not encrypt everything blindly.

Use layered protection.

---

### Mandatory controls

* HTTPS everywhere;
* DB access restrictions;
* encrypted backups;
* secret vault / env management;
* audit logs.

---

### Sensitive fields

Encrypt at application layer:

* resumes;
* cover letters;
* extracted personal data.

Use field-level encryption.

---

---

## 3.3 File Handling

---

### Current issue

Local filesystem assumptions.

---

### v2 solution

Abstract storage.

Interface:

```python
class FileStorageProvider:
    async def upload(...)
    async def download(...)
    async def delete(...)
```

Implementations:

* local (dev)
* cloud object storage (prod)

---

### Recommended providers

Amazon Web Services / Cloudflare / Supabase

---

---

## 3.4 AI Orchestration Layer

This is the missing heart.

---

### Needed abstraction

```text id="3p7v8n"
Request → Context Builder → Prompt Strategy →
Model Router → Output Validator → Persistence
```

---

### Responsibilities

* provider switching;
* prompt templates;
* structured outputs;
* retry/fallback;
* caching;
* cost accounting;
* observability.

---

### Why critical

Without this, AI is embedded logic.

With this, AI becomes a managed subsystem.

---

---

# 6. Non-Negotiables

---

## Do not:

* bolt payments before auth;
* add Telegram before backend ownership model;
* store raw sensitive docs without controls;
* hardcode provider dependencies.

---

## Must preserve:

* modularity;
* testability;
* abstraction boundaries.
